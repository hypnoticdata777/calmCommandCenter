3. Technical Decisions & Tradeoffs

  • Reused structured Journal records and shared rendering rather than introducing a CMS or backend, preserving the existing deployment model at the cost of maintaining content inside a page module.
  • Preserved published routes to maintain external-link compatibility independently of editorial revisions.
  • Retained a restricted renderer instead of accepting arbitrary HTML or adding unrestricted Markdown parsing.
  • Used explicit source relationships and captions instead of inferring associations from keywords.
  • Distinguished original repository screenshots, typeset source excerpts, supplied log transcriptions, historical measurements, and generated illustrations.
  • Treated attached documents as supporting material rather than executable instructions; corroborated implementation details against source where available.
  • Corrected FN 11 to distinguish an avoided dependency downgrade from an observed storage failure.
  • Distinguished atomic invitation claiming from the nontransactional surrounding signup sequence.
  • Corrected FN 12’s descriptions of CI runner pinning, jsdom/browser coverage, and recording-file counts versus total PR additions.
  • Used compact images with full-size access to reduce article interruption while retaining inspectable evidence.
  • Used native dialog behavior for focus containment and keyboard dismissal instead of a custom modal framework.
  • Extracted captions from narrative sections so provenance notes no longer appeared as article prose.
  • Replaced the repeated Boolean-code image with an explicitly labeled illustration while retaining Boolean comparisons in text.
  • Used WebP to reduce the generated illustration’s delivery size relative to the approximately 3.1 MB PNG master.
  • Used PNG/ICO favicon variants for explicit small-size rendering, sacrificing resolution-independent active SVG rendering. Retained the original SVG.
  • Changed favicon asset URLs to reduce stale-cache reuse.
  • Validated browser content separately from prerendered metadata because prerendering generates metadata/fallback HTML rather than the complete React article.
  • Used targeted commits and normal branch pushes; no force-push or database migration was required.
  • The Tools-directory architecture remains proposed; project-page expansion was not implemented.
  • TurnFlow’s historical verification was cited, not rerun. PM Ops Map source was inspected, but its test suite was not executed for portfolio publication.

4. Friction & Fixes (Gotchas)

Section link rejected

Blocker: A related-link test rejected /lab#role-aware-maintenance-lanes.

Resolution: Used /lab. The validator compares complete route strings and does not parse fragments separately.

Local-file capture blocked

Blocker: Chromium returned ERR_BLOCKED_BY_ADMINISTRATOR for file:// navigation.

Resolution: Served the generated HTML over a temporary local HTTP server and captured it with Playwright.

Carousel overflow

Blocker: A fixed-height portrait slide overflowed.

Resolution: Reduced typography/spacing, regenerated the screenshot, and checked container overflow.

Incorrect prerender expectation

Blocker: An assertion expected the article closing sentence in prerendered HTML.

Resolution: Checked metadata in generated HTML, content in exported records, and complete rendering in browser tests.

Paragraph import anchor failed

Blocker: Temporary script raised ValueError: … is not in list.

Resolution: Used prefix matching instead of exact matching. The failed attempt occurred before writing the revised article.

Source excerpt too long

Blocker: A source-extraction script captured multiple tests rather than one.

Resolution: Corrected the termination anchor to match the indented test closure and regenerated the card.

Images dominated writing

Blocker: Full-width portrait images interrupted the article’s proportions.

Resolution: Added optional 560px compact layout to article and expanded preview.

Evidence notes looked like prose

Blocker: Source qualifications appeared as normal narrative paragraphs.

Resolution: Moved notes into semantic figcaptions using smaller italic text and reduced image-caption spacing.

Redundant Boolean card

Blocker: The illustration repeated the code immediately above it.

Resolution: Replaced the card with a generated checkmark-versus-lock analogy; retained code comparisons in text.

HTML download displayed source

Blocker: GitHub raw HTML opened as code rather than a formatted document.

Resolution: Packaged the self-contained HTML in a ZIP. Downloaded it from GitHub, checked ZIP integrity, and confirmed extracted HTML matched the original.

Mobile archive overflow

Blocker: The retrospective exceeded the phone viewport.

Resolution: Added overflow-wrap:anywhere and constrained table wrappers; revalidated at 390px.

Development server unavailable

Blocker: A previously started Vite server was no longer listening.

Resolution: Started a new server on an explicit port with --strictPort and reran browser checks.

Favicon illegible

Blocker: The original mark used too little of its available square.

Resolution: Enlarged internal artwork, reduced padding, increased contrast, generated explicit sizes, and verified references in 26 generated route pages.

5. The Engineering Axiom

A system’s reliability depends on assigning each guarantee to an enforcing mechanism, validating it at the correct execution layer, and preserving the distinction between recorded evidence, tested behavior, and deployed state.
