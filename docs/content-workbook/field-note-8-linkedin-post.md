# LinkedIn Post For Field Note 8

I used to think "we need more people" was mostly a capacity question.

More work means more hours.

More hours means more people.

Simple, right?

Not always.

This week, my code gave me a very clean operations lesson.

The project passed 286 tests. Then I tried to install it on a fresh server, which is basically a clean machine with none of my laptop's memory or accidental help.

It failed in seconds.

Not because the app was broken.

Because my laptop had been quietly remembering things the project had not written down.

That is the same thing I have seen in property management teams:

The task "works" because one coordinator remembers the owner texted directly.

The task "works" because one admin knows where the hidden setting lives.

The task "works" because one person remembers whether the vendor was waiting on access or approval.

But if the next person has to ask around to find where things stand, the system is not really running yet.

It is running on someone's laptop.

So Field Note 8 is about the four clocks every task runs on:

1. Doing time
2. Finding time
3. Waiting time
4. Re-explaining time

Hiring adds doing time.

That matters.

But if finding, waiting, and re-explaining are leaking everywhere, a new hire receives more than work. They receive confusion.

Before you count people, count loops.

Can the task be found?

Can it be handed off?

Can it close without one person carrying the whole memory of the room?
